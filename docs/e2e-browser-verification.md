# End-to-end browser verification

The React production preview was configured for the isolated E2E backend at `http://127.0.0.1:4527` and opened at `http://127.0.0.1:4274`. After correcting loopback CORS and restarting with a test-only rate limit, the dashboard hydrated successfully.

The browser displayed a healthy backend with `11/11 checks`, `SQLite` persistence, `03` ready fixture agents, `08` tracked tasks, `07` completed tasks, an `88%` mission pulse, `WebSocket synced`, and an `open` live event stream. The event feed rendered session stops, terminal output and exit, and task completion events. Fixture agents appeared in the agent council cards with `/bin/cat` runtime metadata.

Two defects were found and fixed during the loop. The terminal creation route serialized an unresolved promise and returned an empty 201 body; it now awaits `terminal.open` and returns a concrete session record. The browser preview initially received failed fetch/internal errors because CORS allowed only a fixed port list and the high-volume simulation hit the default rate limiter; CORS now allows loopback origins on arbitrary local ports, and the rate limit is configurable through `UTHARNESS_RATE_LIMIT` while retaining the default of 120.
The populated dashboard command palette opened successfully and exposed refresh, agent scan, theme toggle, and module launch actions. Selecting Open Agents switched the shell to the Agents module without losing the live counts: 13 registered agents, 11 healthy checks, 3 ready fixture agents, 8 tracked tasks, and an open stream. The module showed the live-contract explanation and a working Scan now control.
While the Overview page remained open, a new task was created and transitioned through running to completed via the backend. The frontend updated without a page reload: tracked tasks changed from 8 to 9, completed tasks from 7 to 8, mission pulse from 88% to 89%, and the live feed rendered `task.created`, `task.running`, and `task.completed` events for the probe task. This confirms WebSocket-driven state refresh and event rendering.
The backend was stopped while the dashboard remained open. The frontend correctly changed its shell beacon to `CLOSED`, displayed `Reconnecting`, and preserved the last-known REST data and event history. After restarting the backend on the same database, the frontend automatically recovered to `EVENT STREAM ONLINE`, `WebSocket synced`, and `STREAM OPEN`, with 13 registered agents, 9 tracked tasks, and 8 completed tasks intact.
The rebuilt backend was then verified on the default dashboard port with successful responses from the new `/api/team-members` and `/api/workflow-runs` contracts, alongside the existing health, agents, tasks, sessions, teams, memory, MCP, models, providers, permissions, approvals, terminal, and audit routes.
The rebuilt dashboard now renders the Tasks surface as a live table with status filtering, task creation, and queued/running/failed transition controls; the Sessions surface renders persisted PID, agent, status, working directory, model, and timestamps, with stop controls for active runtimes. Both surfaces were opened successfully in the browser using the default local backend.
Teams now renders the persisted E2E Agent Council with three assigned members, its mailbox message, a real Run action, agent-assignment checkboxes, team creation form, and message composer. Workflows now renders the persisted three-step dependency graph, completed run history, task-step selection, and a real Run action.
Memory now renders a deliberate empty state and a controlled scope/key/value form; the browser accepted a `workspace / loop-status` entry before submission.
Submitting the Memory form persisted the entry, displayed a success notice, and rehydrated the table to one entry and one scope. MCP renders an empty state plus real stdio/SSE/HTTP transport selection, endpoint, command, and registration controls.
Models renders independent provider and model catalogs with registration forms, while Permissions renders six persisted local policy rules, an approval queue empty state, and real access-request and rule-storage forms.
Terminal renders the persisted stopped PTY session, its streamed `terminal.output` log, a working-directory opener, and disabled-until-open input/send state. Audit renders six persisted permission events with actor/action/resource/outcome/metadata columns and a live filter field.
The Electron wrapper was smoke-tested under a virtual display. The first run exposed an actual preload-format defect (`Cannot use import statement outside a module`) because the ESM TypeScript output was loaded as an Electron preload. The wrapper now uses a copied CommonJS `preload.cjs` bridge, retains `contextIsolation`, `sandbox`, and `nodeIntegration: false`, and starts successfully without preload-load errors; only the expected headless GPU/CSP warnings remain.
