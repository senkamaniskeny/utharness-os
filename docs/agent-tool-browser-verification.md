# Agent tool catalog browser verification

The production preview at `http://127.0.0.1:4274/` was built against the isolated backend at `http://127.0.0.1:4591` and loaded successfully with an open WebSocket stream.

The Agents surface rendered **50 catalog tools**, **27 local CLI entries**, official source links, mode filters, search, Select controls, Install or Official setup actions, and the selected runtime state. The Codex CLI card rendered the locally bundled official OpenAI mark and showed `available` after installation and discovery. OpenHands, Cline, Goose, Gemini CLI, and other catalog entries rendered their bundled official marks when a vetted asset existed; entries without a vetted local asset used the clearly labelled neutral initials fallback.

The dashboard showed the selected tool as `Codex CLI`, and the Agents navigation count reflected 27 registry adapters. The browser showed no crash or hydration failure during initial catalog load. The UI remains within the existing green Liquid Glass / 3D HUD / pressed-control language.

The Codex API smoke test found and fixed an important runtime defect before this browser verification: pipe-backed sessions caused `Error: stdin is not a terminal`. SessionManager now uses node-pty for interactive agents, with a child-process fallback. A new Codex chat session produced PTY output without `agent.error`, persisted as stopped after the stop action, and left no Codex process running.
A subsequent browser click attempt triggered a sandbox-side screenshot/upload failure and the browser view reported `about:blank`; this was an automation session reset rather than an application response. The preview and backend processes were independently checked through HTTP and remained available. Browser verification will be reopened after this transient state is cleared.
After restarting the isolated backend with `UTHARNESS_RATE_LIMIT=10000`, the dashboard rehydrated successfully: system health was Healthy, WebSocket was OPEN, and the overview showed 27 discovered catalog adapters and one available Codex CLI. The earlier internal-server-error banner was confirmed to be a 429 rate-limit condition from repeated browser retries, not a route defect. The backend error handler was improved to preserve actionable 4xx messages. The browser screenshot adapter again omitted element indices, but the live DOM successfully activated the Agents navigation through its visible button text.
The browser reopened after the rate-limit correction and the Agents surface hydrated with 50 tools, 27 adapters, Codex selected, and a visible local `available` status. Clicking the visible Codex `Open chat` control produced the success notice `Codex CLI chat session opened`; the live catalog card remained selected and the UI showed the install/discovery state without crashing.
Scrolling to the bottom of the Agents surface showed the selected-runtime Chat setup form with working-directory, model, and first-message fields, plus a Live Agent Chat panel with active Codex session identifier and Stop control. The panel was rendered inside the existing responsive surface grid and remained visible alongside the setup form at the preview viewport.
After rebuilding with live output rendering, the preview rehydrated successfully on the overview with 27 registry adapters, Codex available, WebSocket OPEN, and recent `agent.output` events visible in the telemetry feed. The browser transport intermittently omitted screenshots, but the extracted DOM content remained correct and the backend log showed the real PTY session output stream.

The first rerun failed only because the fixture server had not been started; the corrected run started `scripts/e2e-test-server.mjs` on port 4527 and completed successfully.
